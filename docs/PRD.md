## 1. 项目概述

### 1.1 项目背景

本项目构建一个模拟彩票选号与开奖分析工具，覆盖国内主流福彩与体彩玩法。用户可通过随机机选、策略约束、历史数据推演、手动自选等方式生成号码，并模拟开奖、判定奖级、统计盈亏，直观感受彩票概率。

### 1.2 项目目标

- 支持 **双色球、福彩3D、快乐8、七乐彩、超级大乐透、排列3、排列5** 共 7 种数字型 / 乐透型 / 基诺型彩票。
- 以**确定性规则引擎**实现号码生成、开奖、对奖与奖金计算，规则可配置、可测试。
- 提供**四种选号方式**：机选、策略选号、历史推演、自选（含乐透型复式与数字型玩法）。
- 提供**策略回测**：策略组合与纯随机基线对照，输出命中、相似度、回报率、中奖注数占比。
- 提供**冷热号与形态分析**：热号、冷号、频率热力图、遗漏、和值/跨度/奇偶/012 路。
- 提供**历史数据管理**：PostgreSQL 幂等入库、期号缺口检测、每日自动同步。
- 提供**AI 分析助手**：LLM function calling 编排确定性工具；未配置模型密钥时自动降级为关键词路由。
- 强调教育意义：明确展示“策略不改变中奖概率”“历史数据不能预测未来开奖”。

### 1.3 目标用户

- 彩票玩法学习者
- 概率与统计爱好者
- 对“选号策略”有娱乐性探索需求的用户

### 1.4 重要免责声明

本项目为纯模拟工具，界面须持续展示“模拟用途，不涉及真实投注，请理性看待”提示。所有号码生成基于伪随机数，任何策略均不改变理论中奖概率。历史统计与回测结论均为样本内观察，不代表未来开奖结果。

### 1.6 合规性说明（V1.2 决策）

本工具定位为**纯模拟 / 学习用途**，界面持续展示“模拟用途，不涉及真实投注”。为保证产品在法律与平台规则层面的安全边界，作如下决策：

| 决策项 | 结论 |
|---|---|
| 微信小程序形态 | **放弃**。微信平台对彩票类小程序仅向彩票管理机构开放官方开奖结果查询；“随机模拟选号 / 号码推荐 / 模拟玩法”均属平台未开放类目内容，且平台明确收费选号（含小额打赏）可能被认定为变相售彩服务 |
| 产品载体 | 仅保留 **H5 / 独立网页**（开源仓库 + 自建页面），不做小程序、不依赖应用商店分发 |
| 收款 | 不设任何收费功能。如后续引入自愿打赏，仅限页面外部个人收款码；打赏不绑定任何功能 / 次数 / 权益，不做效果承诺 |
| 内容红线 | ① 不宣传“预测准确 / 提高中奖率 / 跟单能中”；② 不引导“中奖后打赏 / 按中奖分成”；③ 不代收代购真实彩票；④ 不做“捐多给好功能 / 好号码”；⑤ 不规模化建群拉人经营荐号 |
| 法律依据 | 《彩票管理条例》第 38 条及《实施细则》第 7 条（擅自发行销售彩票 / 非法彩票）；《广告法》第 25、28 条与《反不正当竞争法》第 9 条（效果承诺 / 虚假宣传）；两高法释〔2005〕3 号第 6 条（擅自售彩构成犯罪的按非法经营罪处罚） |

> 判断基准：功能免费且对所有人一致、用户自行购彩、不经手资金票据、不承诺效果 → 打赏即赠与；任何一条被突破，性质即翻转为“收费荐号 / 变相售彩 / 赌博”。

### 1.7 设计原则

- **规则与交互分离**：号码池、抽取个数、奖级表集中配置；前端不复制规则逻辑。
- **确定性引擎优先**：LLM 只做意图理解与参数抽取，最终结果由规则引擎计算。
- **配置化扩展**：新增彩种优先通过 `GameConfig` 注册，减少散落分支。
- **匿名会话**：以 `session_id` 区分本地模拟记录，不建设账户体系。
- **移动优先**：所有交互可在触屏上完成，不依赖命令行或弹窗式手动操作。
- **数据与预测分离**：统计面板明确标注“非预测工具”。

### 2.5 实现口径补充

- 每注只兑付所中最高奖级奖金，不兼中兼得。
- 乐透型各号码池独立抽取；双色球蓝球、大乐透后区不与主区混合。
- 七乐彩特别号从基本号池剩余号码中产生，用于二、四、六等奖判定。
- 数字型号码以字符串保存，保留前导零（如 `007`、`00001`）。
- 数字型（福彩3D / 排列3）支持直选、组选3、组选6；排列5 仅按位一致判定。
- 号码随机源使用 `random.SystemRandom`，避免可预测的伪随机序列。

## 3. 功能需求

### 3.1 彩种与规则查询

- `GET /api/games` 返回 7 彩种完整配置：代码、名称、类型、单价、位数、特别号标记、奖池联动标记、玩法名、开奖日、号码池分组、奖级表。
- `GET /api/games/{code}` 返回单彩种配置。
- 前端 `store/game.js` 内置一份只读兜底配置：后端不可用时选号页仍可展示彩种、单价、号码池与开奖日历。
- 应用启动时将 7 彩种配置幂等写入 `games` 表，供数据层与后续扩展使用。

### 3.2 号码生成

请求模型 `PickRequest` 支持 `mode`：`random` / `strategy` / `history` / `manual`。

| 参数 | 约束 | 说明 |
|---|---|---|
| `count` | 1–100 | 机选 / 策略 / 推演生成注数 |
| `history_periods` | 10–200 | 历史推演参考期数（界面 30 / 60 / 100） |
| `play` | 数字型玩法名 | 直选 / 组选3 / 组选6 |
| `compound` | 布尔 | 乐透型自选复式 |
| `zone_inputs` | 分组号码文本 | 自选各号码池输入 |
| `digits` | 数字型号码 | 3 位 / 5 位数字字符串 |

#### 3.2.1 机选（基础模式）

- 输入：彩种、注数（1–100）、数字型玩法。
- 乐透 / 基诺：各号码池无放回随机抽取，升序展示。
- 数字型：按玩法生成；直选为任意 n 位数，组选3 保证含一组对子，组选6 保证三位各异。
- 输出包含 `zones`、`digits`、`display` 与总金额 `cost = 注数 × 单价`。

#### 3.2.2 策略选号（进阶模式）

策略不改变理论中奖概率，界面须明确标注。当前支持：

| 策略 | 实现口径 | 适用彩种 |
|---|---|---|
| 冷热号加权 | 按传入权重（号码 → 权重）做加权抽样；频次数据缺失时跳过该项并提示 | 乐透 / 基诺 |
| 区间均衡 | 将号码池均分为 3 段，每段按名额抽取 | 乐透 / 基诺 |
| 奇偶约束 | 指定奇数个数，其余为偶数 | 乐透 / 基诺 |
| 和值约束 | 限定首个号码池分组的和值区间；前端取理论最小值/最大值的 20%–80% 作为默认区间 | 乐透 / 基诺 |
| 连号控制 | `consecutive=forbid` 时禁止相邻连号 | 乐透 / 基诺 |

- 实现方式：先按约束生成单注，再校验和值与连号；单注最多尝试 300 次，仍不满足时回退为普通机选。
- 数字型彩种没有号码分布策略，界面隐藏“策略”模式，后端按玩法直接机选。
- 前端策略开关默认：区间均衡开启，其余关闭。

#### 3.2.3 历史推演（增强模式）

- 基于 `draw_history` 最近 N 期统计号码出现频率与当前遗漏。
- 乐透型权重：`0.5 + 0.6 × (频率/最大频率) + 0.4 × (遗漏/最大遗漏)`，按号码池分组计算。
- 数字型按位统计 0–9 的频率与遗漏，逐位加权生成，并按玩法校验（组选3 / 组选6）。
- 无历史数据时回退为普通机选。
- 返回 `basis`（推演依据）：参考期数、分组标签、热号 Top6、遗漏号 Top6；选号页展示在“我的号码”上方。

#### 3.2.4 自选录入与复式

- 乐透 / 基诺单式：每个号码池必须选满 `pick` 个、号码范围合法、不得重复。
- 乐透型复式：每区至少选 `pick` 个号码，按组合展开为多注单式票。
  - 展开注数上限 **100 注**，后端先按组合数校验再展开，避免生成大量组合对象。
  - 界面实时显示展开注数与模拟投注金额；超过上限时阻止提交。
- 数字型自选：输入 3 位 / 5 位数字，允许前导零；按玩法校验号码形态。
- 校验失败返回明确错误信息（范围、个数、重复、玩法不匹配）。

#### 3.2.5 数字型玩法

- 福彩3D、排列3：`直选`、`组选3`、`组选6`。
- 排列5：仅按位一致，无玩法选项。
- 玩法只影响对奖条件与奖金，不改变单注命中概率（界面提示）。

### 3.3 模拟开奖与对奖

- `POST /api/draws/simulate`：对一组号码模拟开奖、逐注判定、汇总写库。
- 开奖规则：
  - 乐透型：各号码池无放回抽取。
  - 快乐8：从 1–80 摇出 20 个号码。
  - 七乐彩：额外摇出 1 个特别号。
  - 数字型：随机一个 n 位数，保留前导零。
- 对奖规则按 2.3 节实现；每注只取最高奖级。
- 单注结果包含：序号、号码展示、是否中奖、奖级名、奖级下标、奖金、各分区命中数、命中号码、数字型逐位命中标记。
- 汇总结果：投入 `cost`、中奖 `win`、净盈亏 `profit`、中奖注数 `hit_count`。
- 号码上限：单次对奖 `tickets` 1–200 注；界面最多展示前 20 注。
- 持久化：每次模拟开奖写入一条 `bets` 记录（匿名 `session_id`、彩种、注数、单注金额、开奖号码、最高奖级、奖金、奖池联动开关）。单注时保存具体号码，多注时号码字段留空，仅记注数。
- 大乐透奖池联动开关随请求传入，浮动奖仍按默认值计算。

### 3.4 策略回测

- `POST /api/backtests/run`：基于历史开奖，逐期生成策略号码，并与纯随机基线对照。
- 输入：彩种、回测期数（10–300，后端再按 `BACKTEST_MAX_PERIODS` 截断）、每期注数（1–100）、策略参数。
- 指标：
  - 平均命中数 `avg_hits`
  - 平均相似度 `avg_similarity` = 单注命中数 / 该彩种总抽取数；数字型按是否中奖计 0/1
  - 随机基线命中 / 相似度
  - 显著性 `is_significant` = 策略相似度高于基线且命中数不低于基线（演示口径，非统计检验）
  - 总投入 `cost`、总中奖 `total_win`、回报率 `roi`
  - 中奖注数占比 `win_rate` 与基线占比
  - 逐期明细 `detail`，含窗口 10 的滚动均值 `rolling_mean`
- 结果写入 `backtest_reports`，`GET /api/backtests/reports` 按 `session_id` 返回历史报告。
- 回测策略刻意不使用冷热号权重，避免引入未来数据造成前视偏差；界面提示该口径。
- 无历史数据时返回 400，提示先到“数据”页拉取或运行 `fetch_history.py --seed-demo`。

### 3.5 冷热号与形态分析

- `GET /api/analysis/hot-cold?game_code=&periods=`：最近 N 期频次统计（N 截断到 1–500）。
  - 乐透 / 基诺：按号码池返回热号 Top8、冷号 Top8、完整频次字典。
  - 数字型：按位返回 0–9 出现频次。
- `GET /api/analysis/stats?game_code=&periods=`：遗漏与形态。
  - 遗漏：当前遗漏、遗漏 Top8、平均遗漏。
  - 形态：和值（均值/最小/最大/分桶）、跨度、奇偶比、012 路。
  - 数字型按位统计遗漏，并按“各位数字”统计形态。
- 界面 5 个视图：热号、冷号、热力图、遗漏、形态。
- 图表为跨端零依赖实现，使用 CSS 色块与柱状条，不引入 ECharts。
- 数据为空时展示空状态并引导“去数据页”；页面底部固定提示“历史数据不能预测未来开奖”。

### 3.6 历史数据管理

- 数据表 `draw_history` 以 `UNIQUE(game_code, issue)` 约束幂等写入；重复期号执行更新而非新增。
- 期号格式：`年份 + 三位年内期序`（如 `2026100`）；跨年从 `001` 重新计数。
- 数据来源标记：`demo`（演示生成）/ `official`（预留）/ `manual`。
- 首次部署且库中无数据时，启动引导写入每彩种 60 期演示数据。
- 每日定时任务：北京时间 21:35 自动为全部彩种续写 1 期；时间与开关可用环境变量调整。
- `GET /api/data/status`：各彩种已入库期数、最新期号、来源、期号缺口、状态（`ok` / `warn` / `no`）。
  - 缺口检测使用 PostgreSQL 窗口函数 `LAG` 按年份分组比较期序，最多返回 8 条。
- `POST /api/data/fetch`：手动补拉，支持指定彩种与 1–200 期；当前数据源为演示生成器，官方抓取为后续扩展点，接口契约保持不变。
- `GET /api/data/history`：按期号倒序返回最近 1–50 期，供“最近开奖”展示。
- 数据页只保留必要功能：可折叠的数据源状态、自动同步说明、立即拉取、最近开奖浏览；不再提供 CSV 导入/导出。

### 3.7 AI 分析助手

- `POST /api/agent/chat`：SSE 流式对话；`POST /api/agent/chat-sync`：非流式接口（原为小程序端设计，小程序形态已放弃后保留，供低带宽 / 兼容场景使用）。
- 主路径：OpenAI 兼容 Chat Completions + function calling，最多 6 轮工具调用。
- 工具集（5 个）：
  1. `generate_picks`：机选 / 策略 / 自选生成
  2. `simulate_draw`：模拟开奖并对奖
  3. `query_hot_cold`：冷热号统计
  4. `get_game_rule`：彩种规则与奖级
  5. `run_backtest`：策略回测
- 未配置 `LLM_API_KEY` 时自动降级为内置关键词路由，覆盖冷热号、规则、回测、选号、开奖引导等意图。
- 系统提示词要求：娱乐/学习用途、不涉及真实投注、策略不改变中奖概率、涉及概率必须附带免责提醒。
- 前端 AI 悬浮球：Markdown 渲染、复制、分享；对话历史本地持久化，最多保留 50 条。

### 3.8 我的（本地记录与偏好）

- 模拟开奖成功后，将记录写入本地存储 `sg_records`，最多保留 20 条。
- 记录字段：彩种、注数、号码摘要、结果、投入、中奖金额、时间。
- “我的”页展示累计模拟次数、累计投入、累计中奖、净盈亏；仅统计含金额字段的新记录。
- 支持清空本地记录。
- 偏好设置：
  - 一等奖模拟值展示（当前固定展示 500 万，仅作说明）。
  - 大乐透奖池联动开关本地保存（`sg_pool_high`）；实际模拟以选号页当前开关为准，其默认值来自彩种配置 `pool_high`。
  - 默认注数展示。
- 关于区：免责声明、数据来源、版本号。

### 3.9 竞彩足球（预览）

- 独立页面 `pages/jingcai/jingcai`，以“规划中”预览形态呈现。
- 展示示例赛事、胜平负赔率、玩法规划（胜平负、让球胜平负、比分、总进球、半全场、串关）与上线前准备。
- 示例赛程与赔率均为演示数据，不接官方接口，不支持投注操作。

- 分析 / 回测 / 数据页共享当前彩种选择。
- 所有帮助提示通过 `tip-dot` 居中弹窗展示，长内容可滚动，必须提供关闭按钮。

## 7. 验收标准

| 编号 | 标准 |
|---|---|
| A1 | 7 种彩种均可按规则生成号码；乐透型升序无重复，数字型保留前导零 |
| A2 | 双色球、福彩3D、超级大乐透、排列3、排列5 的对奖与固定奖金符合官方现行规则；大乐透三至七等奖在奖池联动开启时正确上浮 |
| A3 | 快乐8 选十、七乐彩（含特别号）对奖逻辑正确；浮动奖使用简化估算 |
| A4 | 数字型玩法校验正确：直选按位一致，组选3 需含对子，组选6 需三位各异 |
| A5 | 乐透型复式按组合展开正确，展开注数超过 100 注时被拒绝并提示 |
| A6 | 四种选号模式可用；历史推演返回推演依据；无历史数据时回退机选 |
| A7 | 回测输出平均命中、相似度、基线、显著性、ROI、中奖率与逐期明细，并写入 `backtest_reports` |
| A8 | 分析页的热号、冷号、热力图、遗漏、形态均能按彩种展示；数字型按位统计 |
| A9 | 历史开奖幂等入库；期号缺口可检测；每日定时任务可自动续写 |
| A10 | Agent 在配置模型密钥时走 function calling，未配置时走关键词路由；SSE 与同步接口均可用 |

### 8.2 已知实现边界

- 历史数据默认为演示生成，`source=demo`；不能视为官方真实开奖。
- 回测“显著性”为演示口径（策略相似度高于基线且命中数不低于基线），未做统计检验。
- 前端兜底彩种配置不含完整奖级表；后端不可用时选号页可预览号码池与单价，但奖级条件说明为空。
- “我的”页奖池联动开关为本地偏好；实际模拟以选号页开关为准。
- 冷热号策略依赖冷热号接口返回的频次数据；数据缺失时该策略自动跳过并提示。
