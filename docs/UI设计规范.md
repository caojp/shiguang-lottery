# 时光选彩 · 小程序端 UI 设计规范 V1.0

| 项目 | 内容 |
|---|---|
| 产品 | 时光选彩（模拟彩票选号与开奖分析） |
| 前端框架 | uni-app（可编译微信 / 抖音 / 支付宝小程序等多端） |
| 设计稿 | 750 rpx 宽（iPhone 逻辑基准），多端自适应 |
| 版本 | V1.0 · 2026-10-25 |
| 配套后端 | FastAPI + PostgreSQL（games / draw_history / bets / backtest_reports） |

---

## 1. 设计原则

1. **移动优先、单手可达**：核心操作集中在屏幕中下部拇指热区；一次滑动 + 一次点击完成主要流程（选号 → 开奖 → 看结果）。
2. **彩票仪式感**：数字以"号码球"呈现（红/蓝/橙三色体系），开奖结果用大号胶囊 + 滚动动效突出"摇号"体验。
3. **数据可信感**：所有统计（回测、冷热号、频率）用统一深蓝数据色 + 图表表达，杜绝花哨渐变。
4. **"模拟"定位贯穿**：免责声明以横幅常驻顶部，策略选号处固定标注"不改变中奖概率"，与真实购彩明确区隔。
5. **一屏一任务**：选号页聚焦选号，回测页聚焦报告，不做信息堆叠。

## 3. 信息架构

底部 tabBar 共 **5 个入口**：

```
┌────────────┬────────┬────────┬────────┬────────┐
│ 🎱 选号(首页)│ 📈 回测 │ 🔥 分析 │ 🗄 数据 │ 👤 我的 │
└────────────┴────────┴────────┴────────┴────────┘
```

| Tab | 页面 | 核心任务 |
|---|---|---|
| 选号 | index | 彩种切换 → 机选/策略/自选 → 模拟开奖 → 对奖结果 |
| 回测 | backtest | 策略在历史数据上的回测（命中率、相似度、vs 基线） |
| 分析 | analysis | 冷热号、频率热力图、遗漏期数 |
| 数据 | data | 历史开奖数据源管理（拉取状态、导入导出、期号连续性） |
| 我的 | mine | 模拟记录、参数偏好（浮动奖默认值、奖池联动开关）、免责与关于 |

> 后端 Agent 编排层（LLM）对应"AI 智能分析"入口：选号页右下角悬浮球，点击展开对话式分析浮层。

## 4. 页面设计

### 4.1 选号页（首页）

```
┌────────────────────────────────────────┐
│  🎯 时光选彩                     [⚙]  │ 导航栏
│  模拟彩票 · 不涉及真实投注              │
├────────────────────────────────────────┤
│  ⚠ 模拟用途，不涉及真实投注，请理性看待   │ 免责横幅(常驻)
├────────────────────────────────────────┤
│ [双色球][福彩3D][快乐8][七乐彩][大乐透]  │ 彩种胶囊(横向滚动)
│ [排列3][排列5] [竞彩·暂不支持·灰显]      │
├────────────────────────────────────────┤
│  ┌ 机选 ┬ 策略 ┬ 自选 ┐                │ 模式分段器
│  │                                  │
│  │ 【机选】                           │
│  │   注数  [−] 1 [+]   🎲 生成号码     │
│  │   第1注  ●05 ●12 ●18 ●22 ●30 ●33 +●07 │
│  │   第2注  ●01 ●06 ●11 ●19 ●24 ●28 +●02 │
│  │                                  │
│  │ 【策略】  ⚠不改变中奖概率            │
│  │   [冷热] [区间] [奇偶] [和值] [连号] │
│  │   → 参数弹层                       │
│  │                                  │
│  │ 【自选】                           │
│  │   红球点选面板 33 格 + 蓝球 16 格    │
│  └──────────────────────────────────┘│
├────────────────────────────────────────┤
│      🎰 模拟开奖（主按钮·fixed）        │
├────────────────────────────────────────┤
│  开奖号码                              │
│  ●06 ●13 ●16 ●17 ●30 ●32  +  ●16      │
│  ┌ 第1注  三等奖  +3,000 ┐             │
│  └ 第2注  未中奖   —      ┘            │
└────────────────────────────────────────┘
  右下角悬浮：🤖 AI 智能分析（Agent 入口）
```

**关键交互**
- 切换彩种：号码池、策略可用项、规则说明联动刷新；竞彩胶囊灰显不可点，点击 toast"竞彩依赖真实赛果，暂不支持"。
- 机选：注数 1–5（默认 1）；生成后号码卡立即呈现，可再次生成替换。
- 策略：chips 多选，参数通过底部弹层（picker）配置（如和值区间、奇数个数）；启用任一策略即显示"⚠ 不改变中奖概率"。
- 自选：点选式号码面板（优于输入框，符合移动端习惯）；红球满 6 个、蓝球满 1 个后其余置灰；点错可撤销。
- 模拟开奖：按钮点击后号码卡滚动动效（1s 摇号动画）→ 开奖胶囊出现 → 对奖列表逐行高亮，中奖行金球 + 金额。
- AI 悬浮球：展开底部对话浮层，调用后端 Agent（function calling）生成号码/解读数据。

**状态设计**
- 空态：未生成号码时结果区显示插画 + "点上方生成号码，再模拟开奖"。
- 加载态：生成/开奖期间按钮 loading + 号码区 skeleton。
- 错误态：自选校验失败 toast 具体原因（个数/范围/重复）。

## 6. 多端适配要点（uni-app）

- 全部尺寸使用 `rpx`，750 设计稿基准，自动适配微信/抖音/支付宝。
- tabBar 高度预留 `safe-area-inset-bottom`；主按钮同样避让 Home 条。
- 微信端使用 `button` 原生开放能力（分享回测报告）；抖音/支付宝端降级为保存图片。
- 图表库选轻量 canvas 方案（如 `ucharts` / 自绘），避免多端差异。
- 深色模式：V1.0 仅做浅色，深色留待 V1.1。

## 7. 与后端接口的对应（UI 侧）

| 页面 | 接口（FastAPI） | 用途 |
|---|---|---|
| 选号 | `POST /api/draw/simulate` | 生成 + 开奖 + 对奖 |
| 选号·自选 | `POST /api/bets` | 保存投注记录（复式展开） |
| 回测 | `POST /api/backtest/run` | 运行回测，落 `backtest_reports` |
| 分析 | `GET /api/analysis/hot-cold?game=&periods=` | 冷热号/热力图数据 |
| 数据 | `POST /api/data/fetch` / `GET /api/data/status` | 拉取与状态 |
| AI | `POST /api/agent/chat` | Agent 编排层对话 |

## 8. 验收要点（UI）

1. 主流程 ≤ 2 次点击完成一次"选号 → 开奖 → 对奖"。
2. 7 彩种切换无错位、号码池联动正确。
3. 免责与"策略不改变概率"提示在所有相关页面可见。
4. 低端机型（rpx 适配）无横向溢出；safe-area 正确。
5. 空态/加载态/错误态均有明确视觉反馈。
